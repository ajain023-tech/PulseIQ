# Model card — PulseIQ D30 retention model

| | |
|---|---|
| **Model** | `HistGradientBoostingClassifier` (learning_rate 0.05, max_depth 3, max_leaf_nodes 15, l2 1.0, balanced class weights) + isotonic calibration |
| **Artifact** | `artifacts/ml/model.joblib`, metadata in `artifacts/ml/model_meta.json` (features, threshold, split, metrics, git SHA, sklearn version) |
| **Target** | `d30_retained`: a session in the day-30 block after signup |
| **Prediction time** | 72 h after signup |
| **Owner** | Anushka Jain |

## Intended use
- Rank new users by their likelihood of being active on day 30, so that a
  retention campaign can focus on the most at-risk users (the bottom 20 % of
  scores) or a team can study what early behaviour predicts retention.
- **Not for** individual decisions with material consequences such as pricing or
  account actions, and not for real users. It is trained on synthetic data.

## Data
- Generated by `pulseiq generate` (seed 42, 60,000 users over 120 days). Eligible
  population: 45,095 users with a fully observed day-30 block.
- Time-based split: train 31,566 users / validation 6,764 / test 6,765. Positive
  rates are 14.1 % / 14.5 % / 15.3 %.
- Features cover only the first 72 h plus signup dimensions. A leakage test proves
  that removing post-72 h events changes nothing.

Recall is lowest on **web** (0.56 vs 0.76 on iOS). Web users have fewer sessions in
their first 72 h, so the model sees weaker signals for them. Before acting on
predictions, consider a per-platform threshold, or monitor web separately. The
country-tier gaps are small (0.68–0.74).

## Caveats
- The training data is synthetic, with retention drivers planted by construction.
  The model recovers them (top 3 features = the planted drivers), which validates
  the pipeline, not real-world performance.
- Exact-day D30 is noisy, which caps achievable precision.
- Probabilities are calibrated on validation data from March 2025; drift in
  acquisition mix (e.g. more paid social) shifts the base rate.

## Monitoring and retraining plan
- **Retrain monthly**, or whenever the live D30 base rate drifts by more than 2 pp,
  the PR-AUC on the latest matured cohort drops by more than 0.05, or the input
  distributions shift (PSI > 0.2 on `active_days_72h`, `workout_log_72h`, or the
  channel mix).
- Keep the time-based split: always validate on the most recent matured cohort.
- Re-check the fairness table on every retrain.
