# Hackathon pitch — PulseIQ

## One-liner
An open-source product analytics & experimentation platform that **proves its own A/B readouts are
correct**: event pipeline, validated experimentation engine, retention ML and a guarded AI analyst.

## Slide outline (6 slides)
1. **Problem:** experiment readouts get trusted blindly. Broken assignment (SRM), daily peeking
   and ignored guardrails lead to bad launches.
2. **Solution:** PulseIQ, with an event pipeline (dbt + DuckDB), an experimentation engine (SRM,
   CUPED, sequential, Bayesian, decisions), retention ML and an AI analyst, all behind one
   API and dashboard.
3. **Demo:** SRM → INVESTIGATE; CUPED → SHIP; guardrail → KEEP RUNNING; the peeking chart; the
   at-risk users; the AI analyst refusing `DROP TABLE`.
4. **Validation (the differentiator):**
   - a simulator with planted truth;
   - every planted effect recovered within the 95 % CIs;
   - the SRM bug caught and localised to Android;
   - planted retention drivers rediscovered;
   - all numbers generated by scripts, never typed (see the README Key results).
5. **Tech & engineering:**
   - Python, dbt, DuckDB, FastAPI, Streamlit, scikit-learn, lifelines, sqlglot;
   - about 100 tests, a 70-test data contract, CI;
   - Docker, and one command to rebuild everything from a seed.
6. **Impact & next:**
   - trustworthy experiment decisions, shorter tests (CUPED), safe self-serve analytics;
   - next: real event ingestion, a cloud warehouse, uplift modelling, a production LLM eval.

## Judging checklist
- **Working demo:** yes. A local dashboard and API, plus Docker, plus a hosted dashboard once
  you deploy it.
- **Technical depth:** statistics validated against ground truth, leakage-tested ML, guarded
  text-to-SQL.
- **Honesty:** synthetic data is stated up front; limitations are listed in the README and the
  model card.
