## 3. Tasks

### 4.1 Containerise
- `Dockerfile` — multi-stage: builder installs deps into a venv; runtime is
  `python:3.11-slim`, non-root user, `PULSEIQ_SIZE=small` default, healthcheck hitting
  `/api/v1/health`. Image < 800 MB; log the final size.
- `scripts/bootstrap.sh` — idempotent: if the warehouse is missing → `generate`,
  `build`, `analyze --all`, `train`; then exec the requested service.
- `docker-compose.yml` — services `api` (port 8000) and `dashboard` (port 8501),
  shared volume for `data/` and `artifacts/`, `.env` passthrough for LLM keys,
  bootstrap runs once (first service or a one-shot `init` service with
  `depends_on: condition: service_completed_successfully`).
- `.dockerignore` (data, artifacts, .git, legacy notebooks outputs, venvs).
- Makefile: `docker-build`, `docker-up`, `docker-down`.
- Acceptance: on a clean clone, `docker compose up --build` → both services healthy
  in < 5 min; record time in PROGRESS.md.

### 4.2 Deploy (prepare everything; the user clicks "deploy")
Primary: **Streamlit Community Cloud** for the dashboard — needs `requirements.txt`
(export from pyproject), entrypoint `apps/dashboard/Home.py`, and a startup hook that
runs bootstrap in small mode if the warehouse is missing (cache it with
`st.cache_resource`), plus `.streamlit/secrets.toml.example` for the LLM key.
Secondary (optional): **Render** or **Hugging Face Spaces (Docker)** for the API using
the Dockerfile — add `render.yaml` or Space README metadata.
Write `docs/DEPLOYMENT.md` with click-by-click steps for the user, env vars, and
troubleshooting (cold starts, memory limits, missing key → offline AI mode).
Verify locally with `streamlit run apps/dashboard/Home.py` from a fresh directory with
no `data/` (simulates cloud cold start); startup must succeed < 60 s.

### 4.3 README rewrite (most important file in the repo)
Structure, in this order:
1. **Title + one-line pitch:** "PulseIQ — an open-source product analytics &
   experimentation platform: event pipeline, validated A/B testing engine, retention ML,
   and an AI analyst."
2. Badges: CI status, Python version, license, live demo link (placeholder until the
   user deploys).
3. **Hero screenshot or GIF** of the dashboard (docs/images/).
4. **"What it does" — 5 bullets**, each with a result number from artifacts.
5. **Architecture diagram** (mermaid, from roadmap README) + 4-line explanation.
6. **Key results table** generated by `scripts/render_results.py` from artifacts:
   experiment decisions with lifts/CIs, CUPED variance reduction, peeking FPR naive vs
   sequential, model PR-AUC vs baseline, AI-analyst eval score. Never type numbers by
   hand — the script inserts them between `<!-- RESULTS:START -->` / `END` markers.
7. **Quickstart:** Docker (1 command) and local (`make install && make all &&
   make serve`).
8. Tech stack line. 9. Repo structure (clean ASCII/UTF-8 tree). 10. Methodology links
   (docs/). 11. "Why synthetic data?" — honest paragraph on ground truth & validation.
12. Limitations & future work (real event ingestion via Kafka/Redpanda, dbt on
   BigQuery/Snowflake, feature store, auth, React frontend, uplift modelling).
13. v1 → v2 changelog paragraph linking `legacy/`. 14. Author: Anushka Jain + links
   (ask user). 15. License (MIT unless user objects).

### 4.4 Demo kit (`docs/demo/`)
- `DEMO_SCRIPT.md` — a 3-minute talk track with exact clicks:
  (0:00) problem: "teams ship features without trustworthy experiment reads" →
  (0:20) Home KPIs → (0:40) Funnel biggest drop → (1:00) Experiments:
  `streak_reminder` SRM → INVESTIGATE; `paywall_redesign` CUPED → SHIP;
  `onboarding_flow_v2` guardrail trade-off → (1:50) peeking simulation chart →
  (2:10) Retention model: threshold slider, at-risk users → (2:30) AI analyst: ask two
  questions live, one blocked malicious query → (2:50) "proved correct against planted
  ground truth" close.
  Include a 60-second version and a fallback plan if Wi-Fi/LLM fails (offline mode).
- `HACKATHON_PITCH.md` — problem, solution, demo, tech, validation, impact, what's
  next; 5–7 slide outline with one line per slide (the user can build slides later).
- Screenshots of every page in `docs/images/` and a short GIF of the AI analyst if
  tooling allows; otherwise a checklist for the user to capture them.

### 4.5 Resume & interview kit (`docs/career/`)
- `RESUME_BULLETS.md` — 3 versions (Data Analyst, Data Scientist, Analytics/Data
  Engineer), 3–4 bullets each, **numbers pulled from artifacts by a script or verified
  by hand against artifact files with the file path cited in a comment**. Pattern:
  action verb + what + tech + measurable result. Example shape (fill from real data):
  "Built an A/B testing engine (SRM, CUPED, sequential tests) in Python that recovered
  all N planted effects within 95 % CIs and cut CI width by X % via CUPED."
  Plus a 2-line project description for LinkedIn and a one-line GitHub repo description.
- `INTERVIEW_PREP.md` — merge the "Viva questions" from all four phase docs, with
  concise model answers grounded in this repo's actual implementation and numbers;
  add 10 likely follow-ups (system design: "how would this scale to 100M events/day?",
  "how would you move this to BigQuery?", "how do you monitor model drift?").
- `LEARNING_LOG.md` — the "Learn this" topics from all phases as a checklist with
  one-paragraph explanations and links to the files where each concept is implemented.

### 4.6 Final cleanup & audit
- Run everything from a clean clone (`git clone` into a temp dir): `make all`, tests,
  Docker, dashboard. Fix anything broken.
- Search the active tree for: hard-coded paths (`/Users/`), TODO/FIXME, stray prints,
  secrets, empty files, garbled characters, the old Tableau link, numbers in docs that
  don't match artifacts (`scripts/check_numbers.py` greps README/docs for numbers
  inside RESULTS markers and compares to artifacts).
- `docs/FINAL_AUDIT.md` — checklist with pass/fail per item, including a page-by-page
  dashboard check in a real browser (the v1 audit never did this).
- `CHANGELOG.md` (v0.1 = legacy analysis, v1.0 = PulseIQ), `LICENSE`,
  `CONTRIBUTING.md` (short), issue templates optional.
- Update PROGRESS.md with the final status; merge `phase-4-ship` → `main`; after user
  approval, tag `v1.0.0` and push.

## 4. Acceptance checks
```bash
git clone <repo> /tmp/pulseiq-check && cd /tmp/pulseiq-check
docker compose up --build -d && sleep 5 && curl -s localhost:8000/api/v1/health
open http://localhost:8501          # every page loads
make install && make all && pytest -q
python scripts/render_results.py --check   # README numbers == artifacts
python scripts/check_numbers.py
```
Definition of done: clean-clone run works both ways; README renders correctly on
GitHub with real numbers and screenshots; deployment steps verified locally (and
live if the user deployed); demo script rehearsable in ≤ 3 min; resume bullets contain
only verified numbers; FINAL_AUDIT all green or exceptions explained; tagged release
(after approval).
